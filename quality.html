1. Description, Purpose and Boundaries

Test complete user journeys including security and accessibility failures.

Validate complete user journeys and failure paths, not just whether code parses.

Treat testing & accessibility as an independently reviewable capability. Trace its inputs, processing decisions and acceptance evidence before applying it to a live system. The examples define bounded units; external services need separately verified permissions, contracts and environment configuration.

2. Architectural Principles and Decisions

The primary decision boundary is: Run deterministic and integration checks. Application logic and an accountable owner establish this decision. Preserve the input identity and rule revision so its outcome can be investigated.

Prioritize green unit tests hide broken deployment and visual-only status excludes screen readers. Establish checks for these failures before enabling automation. Completion requires evidence for the final step, record evidence and block unaccepted release, rather than merely observing request acceptance.

5. Detailed Mechanics and Topic Features

Test layers

Use focused unit tests for policy decisions, integration tests for database and mail boundaries, contract tests for providers and end-to-end tests for critical journeys. Verify registration → OTP delivery → verification → session → authorized action → logout. Use controlled test mailboxes and provider test modes; never repeatedly send unsolicited test mail.

Security cases

Test authorization and tenant isolation, replay, injection, token expiry, account enumeration, CSRF, CORS assumptions, upload abuse and secret exposure. Include concurrent OTP redemption and session revocation. Scan dependencies and inspect emitted static assets for accidentally bundled secrets.

Accessibility and UX

Use semantic landmarks, labelled controls, keyboard access, visible focus, sufficient contrast and descriptive errors. Test mobile layout, zoom, reduced motion and screen readers. Do not make a countdown the only indication of expiry. Keep OTP entry compatible with paste and assistive technologies; provide a clear resend status without exposing account existence.

Release evidence

Record tested commit, environment, steps, expected and actual results and remaining limitations. A green deployment does not prove application correctness. A syntax check does not establish browser rendering, email delivery or live TLS.

10. Operations, Ownership and Maintenance

Assign a technical owner for testing & accessibility. Review changes to GitHub Actions, Browser test runner, Accessibility tooling against this chapter’s assumptions. Record the dependency contract, environment and last tested revision.

Use the failure matrix to locate uncertain state during incidents. Preserve redacted evidence, restore the approved configuration or apply a reviewed correction, and rerun acceptance checks. Update the review date after provider or architectural changes.
