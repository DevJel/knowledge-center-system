1. Description, Purpose and Boundaries

Implement bounded agents with verifiable tool contracts.

Treat phase 4: agent development as an independently reviewable capability. Trace its inputs, processing decisions and acceptance evidence before applying it to a live system. The examples define bounded units; external services need separately verified permissions, contracts and environment configuration.

2. Architectural Principles and Decisions

The primary decision boundary is: Execute with resource and permission limits. Application logic and an accountable owner establish this decision. Preserve the input identity and rule revision so its outcome can be investigated.

Prioritize prompt injection changes tool intent and agent loops consume unlimited budget. Establish checks for these failures before enabling automation. Completion requires evidence for the final step, validate output and evaluate adversarial cases, rather than merely observing request acceptance.

6. Implementation Pattern and Copyable Code

This focused TypeScript implementation belongs in the trusted application or test layer. Supply identity, permission and provider-verification state from real verified dependencies; do not accept trust flags directly from a browser.

typescript
type ToolName = "knowledge.search";
interface ToolRequest { name: ToolName; query: string; limit: number }
export function parseToolRequest(value: unknown): ToolRequest {
  if (!value || typeof value !== "object") throw new Error("Invalid tool");
  const item = value as Record<string, unknown>;
  if (Object.keys(item).some(key =>
    !["name", "query", "limit"].includes(key))) throw new Error("Unknown field");
  if (item.name !== "knowledge.search") throw new Error("Tool denied");
  if (typeof item.query !== "string" ||
      item.query.trim().length < 1 || item.query.length > 2000) {
    throw new Error("Invalid query");
  }
  if (typeof item.limit !== "number" ||
      !Number.isInteger(item.limit) || item.limit < 1 || item.limit > 10) {
    throw new Error("Invalid limit");
  }
  return { name: item.name, query: item.query, limit: item.limit };
}

Version the implementation with the consuming application and run this chapter’s acceptance checks when its assumptions change. A copied unit does not establish that all external integrations are active.

10. Operations, Ownership and Maintenance

Assign a technical owner for phase 4: agent development. Review changes to Model provider API, MCP server, GitHub Actions against this chapter’s assumptions. Record the dependency contract, environment and last tested revision.

Use the failure matrix to locate uncertain state during incidents. Preserve redacted evidence, restore the approved configuration or apply a reviewed correction, and rerun acceptance checks. Update the review date after provider or architectural changes.
