1. Description, Purpose and Boundaries

Release compatible code and configuration with a reversible plan.

Treat phase 6: deployment as an independently reviewable capability. Trace its inputs, processing decisions and acceptance evidence before applying it to a live system. The examples define bounded units; external services need separately verified permissions, contracts and environment configuration.

2. Architectural Principles and Decisions

The primary decision boundary is: Deploy to isolated staging and exercise journeys. Application logic and an accountable owner establish this decision. Preserve the input identity and rule revision so its outcome can be investigated.

Prioritize schema rollback destroys new data and wrong environment receives secrets. Establish checks for these failures before enabling automation. Completion requires evidence for the final step, promote and observe with rollback available, rather than merely observing request acceptance.

10. Operations, Ownership and Maintenance

Assign a technical owner for phase 6: deployment. Review changes to GitHub Actions, Cloudflare Pages, Cloudflare Workers against this chapter’s assumptions. Record the dependency contract, environment and last tested revision.

Use the failure matrix to locate uncertain state during incidents. Preserve redacted evidence, restore the approved configuration or apply a reviewed correction, and rerun acceptance checks. Update the review date after provider or architectural changes.
