1. Description, Purpose and Boundaries

Make asynchronous work durable and safe under redelivery.

Background work needs a durable state model and an explicit retry budget.

Treat queues, jobs & reliability as an independently reviewable capability. Trace its inputs, processing decisions and acceptance evidence before applying it to a live system. The examples define bounded units; external services need separately verified permissions, contracts and environment configuration.

2. Architectural Principles and Decisions

The primary decision boundary is: Claim with lease and execute bounded handler. Application logic and an accountable owner establish this decision. Preserve the input identity and rule revision so its outcome can be investigated.

Prioritize crash after side effect before acknowledgement and poison message creates retry storm. Establish checks for these failures before enabling automation. Completion requires evidence for the final step, acknowledge success or schedule bounded retry, rather than merely observing request acceptance.

5. Detailed Mechanics and Topic Features

Job lifecycle

Use queued, claimed, succeeded, retry_wait and dead_letter states with timestamps, attempt counts and correlation IDs. Assume at-least-once delivery unless the provider contract says otherwise; make handlers idempotent. Use leases/visibility timeouts so crashed workers do not strand jobs. Bound parallelism to downstream capacity.

Choosing execution tools

Queues decouple producers and consumers; scheduled jobs trigger periodic maintenance; durable workflows coordinate multi-step work; coordinated state handles contention. Keep security-message jobs short-lived. For expensive AI jobs persist progress, cancellation and budgets. Do not use a browser timer as the sole scheduler for critical operations.

Failure and recovery

Classify retryable versus permanent errors. Use exponential backoff with jitter, maximum attempts and a dead-letter path. Preserve enough redacted context to replay safely. Apply backpressure when provider quotas are exhausted. Monitor oldest-job age as well as queue length.

Verification

Test duplicate messages, worker crash after side effect but before acknowledgement, expired leases, poison payloads, retry storms, downstream throttling and safe manual replay. Design compensation for partially completed multi-step workflows.

6. Implementation Pattern and Copyable Code

This focused TypeScript implementation belongs in the trusted application or test layer. Supply identity, permission and provider-verification state from real verified dependencies; do not accept trust flags directly from a browser.

typescript
export function nextRetryAt(
  attempt: number,
  nowMs: number,
  random: () => number = Math.random
): number {
  if (!Number.isInteger(attempt) || attempt < 1 || attempt > 5) {
    throw new Error("Retry budget exhausted");
  }
  const ceiling = Math.min(60_000, 1000 * 2 ** (attempt - 1));
  const sample = random();
  if (sample < 0 || sample >= 1) throw new Error("Invalid jitter sample");
  return nowMs + Math.floor(sample * ceiling);
}

Version the implementation with the consuming application and run this chapter’s acceptance checks when its assumptions change. A copied unit does not establish that all external integrations are active.

10. Operations, Ownership and Maintenance

Assign a technical owner for queues, jobs & reliability. Review changes to Cloudflare Queues, Durable storage, Scheduled trigger against this chapter’s assumptions. Record the dependency contract, environment and last tested revision.

Use the failure matrix to locate uncertain state during incidents. Preserve redacted evidence, restore the approved configuration or apply a reviewed correction, and rerun acceptance checks. Update the review date after provider or architectural changes.
