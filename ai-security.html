1. Description, Purpose and Boundaries

Keep retrieved content and model output outside the trusted policy boundary.

Separate trusted policy and tool permissions from retrieved documents, email bodies and model output.

Treat ai, rag & tool security as an independently reviewable capability. Trace its inputs, processing decisions and acceptance evidence before applying it to a live system. The examples define bounded units; external services need separately verified permissions, contracts and environment configuration.

2. Architectural Principles and Decisions

The primary decision boundary is: Generate with scoped context and approved tools. Application logic and an accountable owner establish this decision. Preserve the input identity and rule revision so its outcome can be investigated.

Prioritize retrieved document injects tool instructions and deleted data remains in embeddings. Establish checks for these failures before enabling automation. Completion requires evidence for the final step, validate citations, arguments and budget before action, rather than merely observing request acceptance.

5. Detailed Mechanics and Topic Features

Knowledge pipeline

Collect approved sources, record provenance and access permissions, parse and chunk documents, create embeddings and index them. At retrieval time filter by tenant/authorization before sending context to a model. Include source references and allow unknown answers. Plan reindexing and deletion so removed private data does not remain retrievable.

Agents and tools

Give each tool a narrow schema and least-privilege credential. Validate arguments outside the model, enforce budgets and require the project’s approval gates for consequential actions. Retrieved instructions must not override system policy. Treat prompt injection as an ongoing threat; a prompt disclaimer alone is not a control.

Evaluation and memory

Use a held-out dataset for groundedness, task accuracy, injection resistance, privacy leakage, tool misuse, latency and cost. Store only necessary user-approved memory with retention and deletion controls. Avoid raw secrets and sensitive identifiers in prompts, embeddings and traces. Log tool decisions and redacted outcomes rather than hidden reasoning.

Deployment decisions

Compare quality, data-processing terms, region, latency and cost using verified current provider information. Treat the legacy playbook’s model names, prices, improvement percentages and autonomy thresholds as examples, not production guarantees.

6. Implementation Pattern and Copyable Code

This focused TypeScript implementation belongs in the trusted application or test layer. Supply identity, permission and provider-verification state from real verified dependencies; do not accept trust flags directly from a browser.

typescript
interface Evidence {
  id: string;
  tenantId: string;
  authorized: boolean;
  content: string;
}
export function buildEvidenceContext(
  tenantId: string,
  records: readonly Evidence[]
): string {
  return records
    .filter(record => record.tenantId === tenantId && record.authorized)
    .map(record => JSON.stringify({
      sourceId: record.id,
      untrustedDocumentText: record.content
    }))
    .join("\n");
}
// Authorization must be established by trusted retrieval logic.
// JSON encoding does not neutralize prompt injection on its own.

Version the implementation with the consuming application and run this chapter’s acceptance checks when its assumptions change. A copied unit does not establish that all external integrations are active.

10. Operations, Ownership and Maintenance

Assign a technical owner for ai, rag & tool security. Review changes to Vector index, Model API, Scoped tool gateway against this chapter’s assumptions. Record the dependency contract, environment and last tested revision.

Use the failure matrix to locate uncertain state during incidents. Preserve redacted evidence, restore the approved configuration or apply a reviewed correction, and rerun acceptance checks. Update the review date after provider or architectural changes.
